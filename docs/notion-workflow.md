# Расширенный процесс в Notion

Для базы, созданной через `prepare.sh`, используй `npm run notion`.
[Настройка и подключение базы](setup.md)

`notion:workflow` нужен командам с отдельным процессом эпиков, историй и релизов.
Он требует своей схемы. Перед работой выполни:

```sh
npm run notion:workflow -- help
npm run notion:workflow -- doctor --strict
```

В базе нужны статусы Идея, Бэклог, Аналитика, Дизайн, Разработка, Тестирование,
Ожидание релиза, Закрыто. Поля: unique_id, Parent item, Тип, Приоритет, Размер,
Технический долг, Дата релиза, Релиз, Баг релиза, Входящие задачи и Релиз-процесс.
Для business-команд нужна ещё база требований с Parent item и Sub-item.

Задай `NOTION_TOKEN`, `NOTION_BACKLOG_DATABASE_ID`, при необходимости
`NOTION_BUSINESS_REQUIREMENTS_DATABASE_ID` и имена полей через `NOTION_*_PROPERTY`.
Их можно хранить в приватном `~/.config/w/notion.env` с правами 0600.
Код задач берётся из unique_id базы; статусы и иерархия этого процесса фиксированы.

Публикация релиза в Notion требует подтверждений от системы установки.
Сам `w-releases` сохраняет результат в `report.txt` и `result.json`;
связь с публикацией настраивает команда. Стандартная база из `prepare.sh`
поддерживает основной CLI; расширенную схему нужно подготовить отдельно.
Дата релиза рассчитывается в UTC; поле `timeZone` в manifest задаёт другой часовой пояс.
