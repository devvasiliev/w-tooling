# Оценка бизнес-эффекта

Business Value оценивает ожидаемый эффект задачи по шкале от −1000 до +1000.
Это прогноз для сравнения задач. Фактический результат команда измеряет после выпуска.
Инструмент подключается отдельно и использует [расширенную схему Notion](notion-workflow.md).

## Подготовка

Замени пример метрик в `config/business-value-model.v1.json` данными своего проекта
и обнови версию baseline. Для запуска нужны n8n, отдельная интеграция Notion и
отдельный ChatGPT login. [Установка окружения](../templates/n8n/business-value/README.md)

В разделе карточки `Данные для оценки` заполни проблему, ожидаемый результат
и затрагиваемую аудиторию или процесс. Для бага добавь ожидаемое и фактическое
поведение; для эпика или истории нужен пользовательский либо бизнес-результат.
У задачи укажи связь с продуктовым эффектом или метку `Техническая задача`.
Пустая проблема или результат останавливают оценку и внешний поиск.

## Как читать оценку

Сравнивай карточки одного типа с одинаковыми `BV версия модели` и `BV baseline`.
Подходят результаты `Оценено` и `Частично оценено`, у которых `BV актуален=true`.
Подзадачи отдельно не оцениваются; значения родителей и потомков не складываются.
Статус задачи и приоритет после оценки остаются прежними.

Модель предлагает изменения метрик. Код проверяет источники, ограничивает изменения
и учитывает охват, срок эффекта и качество доказательств. Для неблагоприятного,
среднего и благоприятного сценария применяются веса 0,50, 0,35 и 0,15.
Вклад метрики равен `weight × 100 × tanh(U / materialityThreshold)`.
Код исключает повторный учёт одной причинной цепочки и округляет сумму вкладов.

При отсутствии доказательств положительный эффект получает пометку `Не оценено`.
Существенный неизвестный риск, способный изменить знак результата, блокирует число.
Внешний источник подтверждается доступным публичным HTTPS URL и остаётся косвенным
доказательством. Ссылка на другую метрику числового вклада не даёт.
Уверенность показывается отдельно и зависит от полноты и качества доказательств.

## Просмотр и публикация

Перед записью покажется прежнее и новое значение, изменения полей Notion и будущий
раздел `Бизнес-эффект` с источниками и неизвестными параметрами. Отмена сохраняет
карточку. Публикация повторно проверяет её состояние и версии; конфликт или истёкший
предпросмотр сохраняют прежний подтверждённый результат.

После изменения карточки оценка становится `Устарело`, число скрывается.
То же происходит при смене модели, baseline или других параметров вычисления.
Новый расчёт запускается отдельно.

## Доступ и данные

n8n хранит граф процесса и ID запусков. Отдельный runner получает токен интеграции
`W Business Value`; Codex получает свой `auth.json` с ChatGPT login. Файлы
credentials хранятся раздельно с правами 0600. Общий desktop auth.json не используется.

В `W_BV_PRODUCT_ALIASES` перечисли названия продукта через запятую. Внешний поиск
получает обезличенное описание. Если закрытые данные нельзя убрать, поиск пропускается.
Передача закрытой карточки в отдельный Codex-сеанс требует
`W_BV_ALLOW_CODEX_SUBSCRIPTION=true`. Модель получает метрики и допустимые границы;
веса и итог считает код. Обычные этапы работают без tools, research использует web search.

Окружение устанавливается в `.project/business-value-runtime`. Перед публикацией
workflow нужны проверка его состава, сборка образов, n8n audit и healthcheck сервисов.
Версии и хеши работающего окружения должны совпадать с установленным manifest.

## Разобрать ошибку

```sh
npm run business-value -- inspect-run RUN_ID --strict
npm run business-value -- cleanup RUN_ID --approved --strict
```

Сначала прочитай отчёт. Cleanup удаляет только управляемые блоки этого запуска;
пользовательский контент сохраняется. Автотесты используют сохранённые ответы
модели. Полный прямой прогон через Codex требует отдельного ChatGPT login и пока
не выполнен.
